# Критерии качества todoc (K1–K30)

Нормативный список критериев, по которым `bench/run_benchmark.py` измеряет систему.
Каждый критерий привязан к требованию `.doc/plan/constitution.md` (FR-*) или к разделу
`.doc/plan/competitive-analysis.md`, из которого он выведен. Балл: `pass` = 1.0,
`partial` = фактическая доля (0…1), `fail` = 0.

Измерения выполняются на копии демо-датасета (`demo/`, 234 документа) с 9 намеренно
внесёнными дефектами как ground truth. Конкуренты измеряются только те, которые реально
установлены и запускаются в этой среде (см. §9).

---

## 1. Контракт (K1–K5) — «один вызов = один результат, который можно разобрать»

| ID | Критерий | Как измеряется | Порог | Основание |
|---|---|---|---|---|
| K1 | stdout — ровно один JSON-конверт | ключи `{schema_version, ok, data, diagnostics, next_actions}` присутствуют и лишних нет | все ключи | FR-8.1, §8.2 |
| K2 | Стабильные коды выхода | ошибка валидации → 3, без Python-traceback | exit 3 | §8.2 |
| K3 | Ошибка использования → 2 | вызов без обязательного `--id` | exit 2 | §8.2 |
| K4 | `next_actions` как часть контракта | ключ есть в успехе, в ошибке и в валидации; при успехе и при диагностике список непустой | ключ всегда + непустые подсказки | FR-5.6 |
| K5 | Discovery типовой системы | `types guide` описывает `dir_type`/`doc_type`/`entity_type`/`relation_type` | оба раздела присутствуют | FR-3 |

## 2. Корректность (K6–K10) — «находит то, что сломано, и не выдумывает»

| ID | Критерий | Как измеряется | Порог | Основание |
|---|---|---|---|---|
| K6 | Детекция дефектов | precision/recall/F1 по 9 внесённым дефектам (битая ссылка, YAML-небезопасный front matter, дубликат ключа, неверная константа, глубина, синтаксис, нарушение схемы, висячая связь, неизвестный тип связи) | F1 ≥ 0.95 | FR-4 |
| K7 | Точные локации | доля диагностик с номером строки | ≥ 0.90 (pass), ≥ 0.50 (partial) | FR-4.3 |
| K8 | Портабельность front matter | каждый front matter разбирается внешним PyYAML (`yaml.safe_load`) | 0 ошибок | §8.2 портабельность |
| K9 | Приоритет источника типа | front matter важнее маски папки: `rule_source = rule:fm-*` | совпало | FR-3.2 |
| K10 | Валидация записей | отказ записи при пропуске обязательного поля и при неизвестном `entity_type`; целостность отношений (`relation.dangling_target`, `relation.unknown_type`); файл при отказе не создаётся | все проверки | FR-6 |

## 3. Детерминизм (K11–K13) — «одинаковый вход → одинаковый выход»

| ID | Критерий | Как измеряется | Порог | Основание |
|---|---|---|---|---|
| K11 | Повторный `scan` идентичен | побайтовое сравнение `data` двух запусков | идентично | FR-8.4 |
| K12 | Чтение не мутирует источники | sha256 всех файлов до/после серии чтений | 0 изменений | FR-2.1 |
| K13 | Идентификаторы диагностик стабильны | `id` диагностик совпадает между двумя процессами | совпали | FR-4.5 |

## 4. Безопасность записи (K14–K16)

| ID | Критерий | Как измеряется | Порог | Основание |
|---|---|---|---|---|
| K14 | `--preview` ничего не пишет | sha256 до/после + план с `target_path` | 0 изменений + план есть | FR-7.1 |
| K15 | create-only | вторая запись того же `record_id` → конфликт | exit 5 | FR-7.3 |
| K16 | Containment | `--out` вне DATA_ROOT (абсолютный путь и `../..`) отклонён, файл не создан | exit 4, файла нет | FR-2.3 |

## 5. Ограниченное чтение (K17–K21) — progressive disclosure

| ID | Критерий | Как измеряется | Порог | Основание |
|---|---|---|---|---|
| K17 | Чтение без селектора | заголовок + оглавление (список заголовков), а не полный текст | заголовки есть | FR-5.6 |
| K18 | Раздел = только раздел | `--section` возвращает ≤ 40 строк, не залезает в соседний раздел, есть `truncated` и breadcrumb `heading_path` | ≤ 40 строк + короче файла | FR-5.8 |
| K19 | `--budget` | объём ответа не превышает бюджет | ≤ budget | FR-5.8 |
| K20 | JSON Pointer (RFC 6901) | чтение значения по указателю + ошибка `docs.pointer_not_found` для несуществующего | значение совпало, exit 3 | FR-5.8, RFC 6901 |
| K21 | CSV-проекция | `--columns` + `--rows` дают ровно запрошенные колонки и строки | точное совпадение | FR-5.8 |

## 6. Поиск (K22–K24)

| ID | Критерий | Как измеряется | Порог | Основание |
|---|---|---|---|---|
| K22 | Качество ранжирования | Recall@3 / Precision@3 / MRR на 12 запросах, разметка построена независимым обходом файлов (без участия todoc) | (Recall@3 + MRR)/2 ≥ 0.90 | FR-5.4 |
| K23 | Детерминизм ранжирования | два запуска одного запроса дают одинаковый порядок | идентично | FR-8.4 |
| K24 | Пагинация | `--cursor` со второй страницы возвращает продолжение без пересечений с первой | > 0 и без повторов | FR-5.8 |

## 7. Устойчивость (K25–K26)

| ID | Критерий | Как измеряется | Порог | Основание |
|---|---|---|---|---|
| K25 | Враждебный ввод | JSON глубиной 5000, CSV на 20 000 строк, пустой `.md`, бинарный файл | конверт, без traceback, exit ∈ {0, 3} | FR-4.7 |
| K26 | Некорректные аргументы | `--cursor abc`, `--cursor -1`, `--line-range abc`, `--line-range 5-2` | конверт с кодом, без traceback | §8.2 |

| ID | Критерий | Как измеряется | Порог | Основание |

| K28 | Тестовый набор | `pytest tests` | 0 падений | — |

## 9. Конкурентные измерения

Сравниваются только инструменты, которые **установлены и запускаются** в песочнице
(доступны PyPI/GitHub). Измеряется не «кто лучше», а проверяемые факты на одном корпусе.

| Инструмент | Версия | Как измеряется |
|---|---|---|
| `obsidiantools` | 0.11.0 | `Vault(root).gather().connect()` на копии демо: время, число заметок, локальные md-ссылки, найденные битые ссылки, backlinks, isolated notes, размер front matter index, число предупреждений о неразобранном YAML |
| `open-knowledge` (`ok`) | 0.28.2 | версия, число подкоманд по `--help`, коды выхода и время `status`/`diagnose` на копии демо, пишет ли что-то в корпус, какие возможности вообще заявлены (validate/index/search/mcp/skills/sync/ui/graph/types/records) |

Отклонены как невоспроизводимые в этой среде: `basic-memory` (требует Python ≥ 3.12,
49 зависимостей), `khoj` (тянет `torch`/`transformers`, 79 зависимостей),
`okf` 0.1.0 (заглушка «Currently in development»), `mdkb` (нет на PyPI).

## 10. Как воспроизвести

```bash
python3 bench/run_benchmark.py --venv /tmp/comp     # полный прогон
python3 bench/run_benchmark.py --quick              # меньше повторов латентности
python3 bench/run_benchmark.py --skip-competitors   # только todoc
```

Результаты: `bench/results/benchmark.json` (машиночитаемый) и
`bench/results/benchmark.md` (таблицы). Прогон не трогает `demo/`: копия создаётся в
`/tmp/todoc-bench-corpus`, входные файлы для проверок записи лежат вне DATA_ROOT
(иначе они сами попадают в индекс как записи).
