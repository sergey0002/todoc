# Приоритеты исправления и критерии приёмки

Приоритеты ниже относятся к исправлениям после аудита. В этой работе исходники не менялись; ни один баг не объявлен исправленным.

| Очерёдность | Работа | Проверяемый результат |
|---|---|---|
| P0 | Существующий BUG-034: containment change target | `../`, абсолютная цель и symlink-выход отклоняются; внешний sentinel не меняется при validate/preview/apply |
| P1 | [CA-001](bugfixes/ca-001-malformed-relations.md), [CA-002](bugfixes/ca-002-invalid-utf8.md): обработка плохих данных | Все команды возвращают диагностический конверт; один повреждённый файл не роняет поиск/валидацию исключением |
| P1 | [CA-005](bugfixes/ca-005-create-only-race.md): конкурентное создание | Среди двух создателей одной цели ровно один успешен; второй получает конфликт; данные победителя сохранены |
| P1 | [CA-006](bugfixes/ca-006-index-publish.md): публикация индекса | Сбой на любом шаге не уничтожает предыдущий читаемый снимок; читатель видит согласованное поколение |
| P2 | [CA-003](bugfixes/ca-003-edit-preview-validation.md): единый план правки | Неверный патч отклоняется на preview; валидный preview показывает именно результат apply для того же хеша |
| P2 | [CA-004](bugfixes/ca-004-zero-limit-cursor.md): диапазоны limit | Недопустимый limit отвергается или имеет явный завершающий контракт; cursor никогда не повторяется без продвижения |
| P2 | [CA-007](bugfixes/ca-007-contract-leaves.md), P15/BUG-021 | Рекурсивный инвентарь всех листьев; отрицательные data-сценарии; guidance из каталога и во всех output-форматах |
| P2 | [CA-008](bugfixes/ca-008-documentation-drift.md) | Оперативные справочники описывают действующий CLI; исторические результаты явно помечены |
| P3 | Производительность и разбиение CLI | Профиль 1k/10k/100k и устранение повторного разбора без изменения контрактов |

## Предлагаемые пакеты изменений

1. Общая политика путей и тесты sentinel для change/history/skills. Учитывать различие между путём из недоверенного документа и явно заданным путём оператора.
2. Типизированные результаты разбора и негативные CLI-контракты: отношения, кодировка, patch/query shape. Не лечить все программные ошибки одним широким `except Exception` без различения причин.
3. Транзакционные примитивы записи и публикации. Отдельно проверить create-only, hash conflict, rollback, отказ fsync/rename и конкуренцию.
4. Согласование документации и generated CLI-примеров после стабилизации поведения.

## Гейты при будущих исправлениях

Изменение `src/`: полный pytest и branch coverage `--fail-under=100`, согласно AGENTS.md. Изменение demo: `validate --root demo --all` с нулём диагностик и `tools/linkcheck.py` с нулём битых ссылок. Сам процент покрытия не заменяет новые сценарии, перечисленные выше.

Перед релизом дополнительно выполнить установку wheel в чистое окружение и матрицу поддерживаемых Python/ОС. Для многопроцессного режима нужен реальный процессный стресс-тест: fault injection этого аудита показывает конкретные окна отказа, но не оценивает их частоту в эксплуатации.
