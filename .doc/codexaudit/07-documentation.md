# Документация, демо и самодокументирование

## Проверенные факты

Первый `validate --root demo --all` вернул 0 диагностик при 476 документах. Первый `tools/linkcheck.py` проверил 1085 относительных ссылок, битых 0. Это синтаксическая и ссылочная согласованность; она не доказывает истинность текста.

Через `types list --root demo` получены 24 типа директорий, 31 тип документов, 25 типов сущностей и 18 отношений. Через `skills tree` — 30 скилов, 3 раздела, 1 muted. Эти числа относятся к фактическому CLI в исследованном checkout, а не к примерам README.

## Подтверждённый семантический дрейф

`docs/state/07-search-and-read.md` утверждает, что cursor не продолжает выдачу, breadcrumb — первые три заголовка, поиск использует первое совпадение, каждый поиск пересобирает индекс, а CSV сначала режется по rows и лишь затем фильтруется. В текущем коде реализованы offset-пагинация, breadcrumb выбранного фрагмента, подбор релевантного окна, переиспользование снимка и фильтрация CSV до rows. Подробнее: [CA-008](bugfixes/ca-008-documentation-drift.md).

Аналогичный дрейф есть в `docs/state/02-architecture.md`: утверждение о безусловной пересборке расходится с `ensure_index`. `docs/installation.md` приводит исторические 437 тестов, старые количества файлов init и setuptools>=68, тогда как pyproject требует >=77. Датированные исторические результаты допустимы, но не должны одновременно выступать актуальными ожидаемыми результатами инструкции.

`AGENTS.md` и контракт упоминают BUG-004 как ограничение replace-only, хотя `write.py:167–220` поддерживает insert_after/delete. В старых закрытых репортах остаются ценные доказательства, но оперативная шпаргалка должна отражать текущие возможности. Не следует удалять историю ради выравнивания текста.

## Экономика агентской работы

Файл может иметь front matter ID, который не совпадает с `doc:<path>`. Например, `notes/agent-contract.md` разрешается в `doc:note-agent-contract`, а HOME — в `doc:home`. Правильный путь: `explain-path` → читать выданный ID. Повторные догадки по пути оказались дороже такого разрешения; этот класс фрикции уже отражён в BUG-013 и не заведен заново.

В данном harness вызовы через PowerShell stdin требуют UTF-8: `$OutputEncoding = [System.Text.UTF8Encoding]::new($false)`. Иначе кириллица превращается в `?` ещё до CLI. Это ограничение передачи аргументов среды и относится к BUG-028; его нельзя выдавать за баг поиска русских разделов. Для `--line-range` принят синтаксис `N-M`, не `N:M`; ошибочные авторские вызовы не являются дефектами парсера.

## Что улучшить

Разделить актуальное руководство, планируемые возможности и исторические журналы. Числа и примеры CLI генерировать из одного проверяемого запуска; для важных примеров сравнивать смысл ответа, а не только существование команды. Использовать один источник готовых команд и проверять, что `next_actions[].argv` запускается в том же root.

Нулевые диагностики и нулевые битые ссылки следует сохранить как обязательные гейты, добавив проверку семантических утверждений документации. Новые баг-репорты должны быть связаны из HOME, а закрытие — менять статус с доказательством фикса, без удаления.
