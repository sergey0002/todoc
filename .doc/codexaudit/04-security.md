# Безопасность и границы доверия

## Модель угроз

Активы: документы и записи DATA_ROOT, файлы пользователя вне корня, история изменений и предсказуемость команд, выполняемых агентом. Возможный источник недоверенного содержимого — импортированный датасет, change-бандл, файл записи, навык и его ресурсы. CLI работает с правами запустившего пользователя; отдельного повышения прав в исследованных путях нет.

Недоверенные данные не должны превращать команду работы с выбранным датасетом в запись за его пределами. Сознательная передача оператором произвольного внешнего пути имеет другую модель угроз: сама по себе она не доказывает эксплуатацию злоумышленником.

## Подтверждённая запись за пределы корня — существующий BUG-034

Независимый сценарий в [reproduce.py](evidence/reproduce.py) создаёт временный датасет и соседний `outside.md`. Дельта содержит `target: ../outside.md`. `change validate` возвращает `applicable:true`, `errors:0`; `change apply --apply` возвращает `applied:true` и меняет внешний файл. Полный результат сохранён в [протоколе](evidence/verification.md).

Путь данных: `collect_deltas` читает target из front matter → `validate_change` соединяет `root / target` → `plan_apply`, `changes.py:525–536`, читает ту же цель → `apply_change`, `changes.py:571–579`, вызывает `atomic_write` без containment-проверки.

Предпосылка эксплуатации: пользователь или агент применяет подготовленный злоумышленником change-бандл. Доступ ограничен правами пользователя и возможностями дельта-операций. Доказаны модификация Markdown-файла-соседа и обход границы каталога; удалённое выполнение кода, доступ администратора и эксплуатация реального окружения не проверялись. Канонический BUG-034 имеет severity `critical`; для приоритизации исправление срочное из-за записи за пределами выбранного корня.

Необходимы общая проверка разрешённого resolved-пути во время планирования и повторное обеспечение границы в момент записи, включая абсолютные пути и symlink-выходы. Одной фильтрации строки `../` недостаточно.

## Другие границы

В `docs new` и большинстве `--out`-сценариев `_contained_out`, `cli.py:107–120`, проверяет resolved-путь. Skills read также проверяет попадание в vault. Эти существующие контроли — основание объединить политику, а не писать ещё несколько несогласованных проверок.

Существующие BUG-035 (history --path) и BUG-036 (skills import --into) учтены по отчётам и соответствующим местам кода. Полное независимое динамическое воспроизведение этих двух багов здесь не выполнено. Для них надо отдельно установить, управляет ли путём только оператор или он может происходить из импортированного материала; нельзя автоматически переносить severity произвольной записи change-бандла на любой внешний путь.

Обнаруженные [CA-001](bugfixes/ca-001-malformed-relations.md) и [CA-002](bugfixes/ca-002-invalid-utf8.md) позволяют одному плохому файлу нарушить работу команд над датасетом. Это подтверждённая проблема устойчивости к недоверенному вводу. Для локального CLI без серверного deployment не заявляется удалённый DoS.

В исследованных runtime-модулях subprocess ограничен git-backend. Он вызывается списком аргументов с timeout; `shell=True` и eval в изученных путях запросов отсутствуют. Это не является полным доказательством отсутствия любых инъекций или секретов во всём репозитории.

## Ограничения

Это локальная ручная проверка, а не завершённый управляемый Codex Security scan. Инициализация управляемого сканирования не вернула scan ID; независимого второго reviewer не было. Сетевые проверки CVE, активных credentials и удалённых сервисов не выполнялись. Полный аудит vendored навыков и их install-скриптов, атак на JSON Schema refs, symlink-гонок и decompression объектов истории остаётся отдельной работой. Исходники и чужие навыки не изменялись.
