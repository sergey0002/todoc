# AGENTS.md — правила работы агентов с этим репозиторием

> Файл для кодинг-агентов (Codex, Claude Code, Cursor и др.). Здесь — как
> работать с системой `todoc` и её демо-датасетом: железные правила сессии,
> команды, границы. Для людей — [README.md](README.md), карта демо —
> [demo/HOME.md](demo/HOME.md).

## Что это за проект

`todoc` — переносимый типизированный слой знаний поверх обычных файлов
(Markdown/CSV/JSON): source-native валидатор, типизированные записи,
ограниченный поиск и чтение. CLI-first и agent-first. **Файлы — источник
истины; индекс и кэш — производные и пересобираемые.**

## Установка

```bash
python3 -m venv .venv                 # PEP 668: глобальный pip в системе запрещён
.venv/bin/pip install -e ".[dev]"
.venv/bin/todoc --version             # todoc, version 0.1.0
```

Нужен Python 3.11+. Без установки: `PYTHONPATH=src python3 -m todoc --version`.

## Железные правила сессии

1. **Работай только через CLI.** Любая операция с демо-датасетом и знаниями —
   команды `todoc` (`docs new/read/search/edit/tree`, `records create/list/read`,
   `validate`, `types …`). Не правь файлы датасета напрямую, когда для этого есть
   команда. Исключение — наполнение тела свежесозданного скелета (`docs new`),
   ограничение BUG-004; после наполнения обязательно чтение назад.

2. **Перепроверяй каждый шаг.** После каждой команды — обратное чтение
   результата (`docs read`, `records read`, `explain-path`); после изменений
   данных — `todoc validate --root demo --all` = 0 диагностик. Не переходи к
   следующему шагу, пока проверка не прошла. Сломалось — фиксируй баг-репорт
   (правило 3), чини, повторяй проверку.

3. **Фиксируй баги сразу.** Дефект или недочёт, найденный при эксплуатации
   (команда дала не то, документация врёт, счётчики разошлись, флаг
   игнорируется), — баг-репорт:

   ```bash
   todoc docs new --root demo --type bug-report --title "BUG-NNN: суть" --dir bugs
   todoc types prompt bug-report --op create --root demo   # инструкция по заполнению
   ```

   Один документ = один баг. Заполни все секции шаблона: шаги воспроизведения
   с точными командами, ожидание против факта, доказательства — выводы CLI и
   `файл:строка`. Статус (`open|triaged|in_progress|fixed|wontfix|duplicate`)
   и `severity` — во front matter. Номер NNN продолжай по папке `bugs/`.
   Репорт не удаляется: закрытие — смена статуса с датой и коммитом в «Заметках».

4. **Review-first.** Записи — только `records create --preview` → `--apply`
   (create-only: дубль отклоняется). Правки существующих md — `docs edit
   --preview` → `--apply` (при конкуренции — `--if-hash`).

5. **Счётчики — от факта.** Источник истины — `todoc types list --root demo`
   и фактический вывод команд, не числа в README. Обнаружил расхождение —
   обнови документ и/или заведи баг-репорт (см. BUG-003 как пример).

6. **Гейты перед коммитом.** Изменения данных: `validate --root demo --all`
   = 0 диагностик + `tools/linkcheck.py` (0 битых). Изменения кода `src/`:
   полный `pytest` и гейт покрытия 100% (`coverage run --branch …`,
   `coverage report --fail-under=100`) — это проектное правило, падение
   останавливает CI.

## Быстрая шпаргалка

```bash
todoc docs search --root demo --query "…" --limit 5        # найти
todoc docs read --root demo --id doc:… --section "…"        # прочитать по секции
todoc docs tree --root demo --max-depth 2                   # карта папок
todoc records list --root demo --type task                  # записи типа
todoc types list --root demo                                # все типы
todoc types prompt <тип> --op create --root demo            # стартовый промпт типа
todoc validate --root demo --all                            # 0 диагностик — гейт
```

Подводные камни: секция `docs read --section` обрезается до 40 строк
(смотри `truncated`, дочитывай `--line-range` — BUG-005); `docs edit` умеет
только замену строк (BUG-004); явный `doc_type` без fm-правила резолвится
в `unknown` (BUG-001 — не создавай новые типы без правил).

## Границы

- Не менять `.todoc/` руками без необходимости: типы и правила — данные,
  правятся осознанно, каждый шаг — через `check-config`/`validate`.
- Никаких фоновых процессов, скрытой сети и `eval`; каждый шаг воспроизводим.
- Не удалять и не переименовывать репорт-документы и журналы; история —
  это часть знания (append-only для версий и репортов).
- Обновлённые счётчики и HOME-карта (`demo/HOME.md`) — часть любого PR,
  меняющего структуру демо.
