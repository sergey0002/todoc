# Правка: `task`

Снимок задачи не редактируется произвольно: это архив момента. Допустимые правки —
исключительно санитарные (маскирование секрета, битая ссылка на вложение) и делаются
review-first через `docs edit`-механику записей (patch + hash).

## Когда вместо правки — новый снимок

- Изменился статус/назначенец/описание в трекере → новый снимок с новым `fetched_at`
  (конвенция датасета: где хранить историю снимков — решения за проектом;
  по умолчанию дубль `jira_key` запрещён, поэтому снимки-версии называются
  `task:<project>-<key>-v2` и связаны `supersedes`).

## Санитарная правка

1. Прочитать запись и хеш: `todoc records read --id <record_id> --output json`.
2. Подготовить точечный патч (только изменяемые поля), предпросмотр:

   ```bash
   todoc records read --root KB --id <id> --output json   # current hash
   ```

3. Применить только с явным согласием; после — `todoc validate --root KB --all` (0 диагностик).

## Запрещено

- Менять `jira_key`, `record_id`, `fetched_at`, `comments[]` задним числом.
- «Обновлять до актуального статуса» вручную — статус меняет только новый снимок из трекера.
- Удалять комментарии или вложения из истории.
