# Создание: `plan`

План изменений кода, который исполняет агент **без контекста** — ни кодовой базы,
ни переписки. План несёт всё: какие файлы, какие имена и сигнатуры, какие значения
из спеки, какой тест доказывает каждую задачу. Один план = одна подсистема,
дающая на выходе работающий тестируемый результат; несколько независимых подсистем
→ отдельные планы.

## Как создавать

1. Взять шаблон: `.todoc/doc_types/plan/template.md`.
2. Создать одной командой (create-only):

   ```bash
   todoc docs new --type plan --title "<Название>" --dir plan
   todoc validate --root KB --all   # 0 диагностик
   ```

   `docs new` проверит структуру; отказ `types.template_invalid` чинится в
   документе, не обходом.

## Правила (из лучших практик агентного планирования)

- **Шапка**: Цель — одно предложение; Спека — путь к идее/дизайн-доку (план
  аргументирует от неё); Стек.
- **Кусочки 2–5 минут**: шаг = одно действие (падающий тест → убедиться в падении →
  реализация → убедиться в проходе → коммит). Задача ≤ сессия.
- **Точные файлы**: пути целиком; для Modify — диапазон строк; тесты — отдельным путём.
- **Интерфейсы**: Consumes/Produces с точными сигнатурами — исполнитель задачи видит
  только её, соседние имена он узнаёт из этих блоков.
- **Верификация каждой задачи**: команда + ожидаемый вывод; финальная проверка —
  end-to-end, как пользователь (CLI/эндпоинт/сценарий), не только внутренний assert.
- **Глобальные ограничения дословно** из спеки/конституции — по строке; они входят
  в каждую задачу неявно.
- **DoD до кода**: пороги тестов, ревью, доки, метрики — иначе «готово» означает
  «написано на моей машине».
- **Риски**: вероятность/влияние/митигация/владелец; риск без митигации не пишется.

## Запрещённые заглушки (план-инвалид)

- `TBD`, `TODO`, «сделаем позже», «заполним деталями».
- «Добавить валидацию» / «обработать ошибки» / «написать тесты» — без кода теста
  и без точного поведения.
- «Как в задаче N» — повторить код: задачи читают вразнобой.
- Шаг «что делать» без «как» (код-шаг без блока кода; верификация без команды и
  ожидаемого вывода).
- Ссылки на функции/типы, не определённые ни в одной задаче.

## Самопроверка перед сохранением

1. **Покрытие спеки**: каждое требование спеки → задача, которая его реализует;
   пробелы закрыть задачами или явно во «Вне скоупа».
2. **Скан заглушек**: найти запрещённые формулировки выше — исправить.
3. **Консистентность имён**: сигнатуры и имена в поздних задачах совпадают с
   определениями в ранних (`clearLayers()` в задаче 3 ≠ `clearFullLayers()` в 7 — баг).

Практики формата: superpowers/writing-plans (план для инженера с нулевым контекстом,
кусочки, no-placeholders, самопроверка), Spec Kit `/tasks` (фазы с чекбоксами),
Anthropic plan-mode (план коммитится; чекбокс — в коммите шага), инженерные шаблоны
(In/Out of scope одинаковой строгости, DoD до разработки, риски с митигациями).
