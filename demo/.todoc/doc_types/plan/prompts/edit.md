# Правка: `plan`

План — живой документ, но правки строго разделены: **прогресс** правит исполнитель,
**содержание** — только до начала соответствующей задачи и review-first.

## Что правится свободно (исполнителем, в коммите с кодом)

- Чекбоксы выполненных шагов (`- [ ]` → `- [x]`).
- Раздел 8 «Прогресс и отклонения»: что не собралось, что выбрано вместо планового.

## Что правится с согласованием (до начала правимой задачи)

- Непомеченные шаги, файлы, сигнатуры в задачах, DoD, критерии успеха, риски — правятся напрямую в файле плана после согласования смысла, затем сразу запускается `todoc sync`:

```bash
todoc sync --apply --root KB <путь-к-плану.md>   # обновит updated, историю, индекс и проверит 0 диагностик
```

## Запрещено

- Переписывать выполненные шаги задним числом: выполненное помечено чекбоксом,
  «сделал иначе» фиксируется в разделе 8, а не ретушировкой шага.
- Добавлять задачи без Файлов/Интерфейсов/верификации — новый шаг по правилам
  create (no-placeholders действует и на правки).
- Снимать `Вне скоупа` молча: расширение скоупа — решение пользователя, отражается
  в разделе 8 + правке секции с согласия.

## Правка = новая ревизия

Существенное изменение подхода (архитектура, декомпозиция) — append новой задачи /
новой ревизии в раздел 8; правка истории ревизий запрещена (append-only).

> **Даты:** поле `updated` во front matter бампит движок при `todoc sync` — руками не трогать. Связал документ с другим — добавь/обнови `related`-wikilink (`[[имя-без-.md]]`).
