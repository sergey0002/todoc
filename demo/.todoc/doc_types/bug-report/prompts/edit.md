# Правка: `bug-report`

Правка репорта — только вперёд по жизни бага: уточнение шагов, добавление
evidence, смена статуса. Переписывание задним числом запрещено: репорт — журнал,
а не эссе.

## Правила

1. Правка через review-first: `todoc docs edit --root KB --id <id> --patch-file F --preview`,
   затем `--apply` (и `--if-hash` при конкуренции).
2. Смена статуса — во front matter (`status:`/`severity:`) + строка в «Заметках»:
   `fixed 2026-11-26, commit <hash>` или причина wontfix.
3. Шаги воспроизведения и «Доказательства» после закрытия не переписываются:
   уточнение — новым пунктом с датой.
4. После правки: `todoc validate --root KB --all` — 0 диагностик.

> **Даты:** поле `updated` во front matter бампит движок при `docs edit --apply` — руками не трогать. Связал документ с другим — добавь/обнови `related`-wikilink (`[[имя-без-.md]]`).
