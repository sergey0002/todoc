# Правка: `idea`

Правка идеи — построчная и review-first: сначала предпросмотр диффа, потом применение.

## Как править

1. Прочитать текущее состояние и хеш:

   ```bash
   todoc docs read --root KB --id <document_id> --output json
   ```

2. Подготовить файл патча (построчные замены) и посмотреть дифф:

   ```bash
   todoc docs edit --root KB --id <document_id> --patch-file patch.txt --preview
   ```

3. Сверить дифф с замыслом, затем применить:

   ```bash
   todoc docs edit --root KB --id <document_id> --patch-file patch.txt --apply --if-hash <hash>
   ```

4. Проверить целостность: `todoc validate --root KB --all` — 0 диагностик.

## Правила

- Не переписывай чужую идею молча: содержательные смены позиции оформляй как
  «Обновление <дата>: <что и почему изменилось>» в разделе «Статус».
- Обязательные разделы («Суть», «Проблема», «Предложение») нельзя удалять —
  валидатор вернёт `markdown.section.missing`.
- Ссылки после правки должны вести на существующие файлы: битая ссылка = диагностика.
- Повышение статуса (идея → план) — это не правка идеи, а создание plan-документа
  и ссылка из идеи на него. Идею не переписывать под принятое решение.
- Свободные поля front matter (например `status`) меняются в том же патче, если смысл изменился.
