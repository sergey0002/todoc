# Создание: `idea`

Документ-идея фиксирует предложение до того, как оно доросло до плана. Create-only:
новый файл, перезапись существующих документов запрещена.

## Перед созданием

1. Проверь дубли: `todoc docs search --root KB --query "<тема>" --limit 5` — если идея уже
   описана, дополняй существующую (прямая правка + `todoc sync --apply --root KB <путь>`), не создавай вторую.
2. Уточни у пользователя только недостающее: суть, проблему, ожидаемый эффект. Ничего не выдумывай.

## Как создавать

1. Взять шаблон: `.todoc/doc_types/idea/template.md`.
2. Создать документ (create-only):

   ```bash
   todoc docs new --apply --root KB --type idea --title "<Название идеи>" --dir ideas
   ```

3. Заполнить разделы (минимум обязательных три: «Суть», «Проблема», «Предложение»):

   - **Суть** — 1–2 фразы, что предлагается. Без маркетинга.
   - **Проблема** — какая боль, что сейчас не работает, на ком и когда болит.
   - **Принципы** (опционально) — правила, которым должно следовать решение.
   - **Предложение** — механика, данные, типы, шаги. Формулировки проверяемые:
     «таблица X хранится в Y», «команда Z возвращает W», а не «сделаем удобно».
   - **План внедрения** (опционально) — фазы 0–5 с критериями приёмки на каждую фазу.
   - **Открытые вопросы** — что не решено; честный список, не пустой раздел.
   - **Связанные документы** — относительные ссылки только на существующие файлы.

4. Проверить структуру и ссылки — ожидание 0 диагностик:

   ```bash
   todoc validate --root KB --all
   ```

5. Добавить ссылку на новую идею в `HOME.md`, раздел «Идеи».

## Правила качества

- Проблема — до решения: читатель должен понять боль, не дочитав до «Предложение».
- Одна идея — один документ. Сопутствующие мысли — в «Открытые вопросы», не в эту идею.
- Не дублировать то, что уже есть в `plan/`: сначала поиск, потом письмо.
- Front matter: `id` (doc:…), `title`, `doc_type: idea`, `lang`, `status` (например `captured`).

## Именование файла

Заголовок документа — на русском и живёт в метаданных: поле `title` во front
matter (md) или поле `title` записи (json). Имя файла — на английском
(латиница, kebab-case); заголовок и имя файла независимы. При кириллическом
заголовке создавай документ с явным путём:
`todoc docs new --apply --path <dir>/<english-slug>.md` (слаг из заголовка наследует
кириллицу — BUG-006). Поле `name` для заголовка не вводится: `title` — уже
стандарт, дубль = два источника истины. Существующие кириллические имена —
legacy, не размножать. Подробно: `notes/agent-contract.md` → «Именование
документов».

> **Даты:** поля `created` и `updated` во front matter ставит движок (`docs new`) — руками не заполнять и не редактировать.
