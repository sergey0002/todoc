# Создание: `flow-doc`

Эталон бизнес-флоу: state machine + таблица решений (истина) + flowchart + lineage. md — витрина; истина — записи flow/rule (см. entity-catalog).

## Как создавать

1. Источники — только существующие данные, ничего не выдумывай: каждый факт со ссылкой
   на источник (запись/документ/команда).
2. Создать одной командой (create-only, явный путь для латинских имён):

   ```bash
   todoc docs new --apply --root KB --type flow-doc --title "<Название>" --path <папка>/<имя>.md
   todoc validate --root KB --all   # 0 диагностик
   ```

3. Наполнить тело по шаблону (`.todoc/doc_types/flow-doc/template.md`):
   заменить плейсхолдеры фактами, комментарии-подсказки удалить.
   Правка после создания — прямую правку файла + `todoc sync --apply --root KB <путь>`,
   чтение назад — `docs read --section ...`.

- **Колонка «Режим»**: каждый шаг таблицы — `auto` (действовать автоматически) или
  `ask-user` (спросить человека; указать ветку по умолчанию на случай отказа/таймаута).
  Пусто = auto. Валидатор таблицу не парсит — режимы держит эта конвенция,
  движок проверяет секции и front matter.

## Запрещённые заглушки

- TBD/TODO/«как в задаче N» — не оставлять в тексте; нет данных — раздел с пометкой
  «нет» или открытый вопрос в соответствующую секцию.

## Самопроверка

- `docs read --section` по каждой обязательной секции читает фактическое содержимое.
- Покрытие: все required-секции заполнены → скан заглушек (TBD/TODO) пуст →
  скан значений «Режим» (допустимо: auto | ask-user | пусто) → консистентность
  имён (flow:/rule:/change: ID совпадают с записями).
- `todoc validate --root KB --all` — 0 диагностик.

## Именование файла

- Русский `title`, файл — на английском (слова-дефисы, латиница), канон:
  `notes/agent-contract.md`; папка — по типу: flows/ (flow-doc), specs/ (spec-doc),
  reports/ (task-report и release-note).
