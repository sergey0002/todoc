# 06. Валидация и диагностики

`check-config` проверяет загрузку конфигурации, правила и типы. `check` и `validate --all` читают исходные файлы, применяют наборы правил, проверяют структуры и схемы, локальные ссылки, записи и отношения. `types metadata` показывает нарушения профиля документов. `doctor` проверяет выбранные аспекты конфигурации, Python и индекса. `doctor --fix` готовит план ремонта производного индекса, а `--apply` выполняет его.

Диагностика содержит `code`, `severity`, `path` и `message`. Валидатор добавляет `dataset_id`, стабильный `id`, `location`, `evidence` и `suggested_fixes`. Коллекции могут выдавать более компактные сообщения. Координаты читаются как строка и колонка либо JSON Pointer. `data.meta.complete` указывает, завершён ли обход.

| Пример кода | Причина или результат |
|---|---|
| `config.invalid_schema` | Некорректная конфигурация |
| `document.schema_violation` | Данные документа не проходят схему |
| `record.schema_violation` | Запись не проходит схему сущности |
| `markdown.front_matter.yaml_unsafe` | Front matter выходит за поддерживаемый профиль |
| `markdown.link.target_missing` | Не найдена цель локальной Markdown-ссылки |
| `relation.dangling_target` | Цель отношения отсутствует |
| `filter.invalid`, `fields.unknown` | Неподходящий фильтр или поле проекции |
| `cursor.invalid` | Курсор не подходит к выборке или снимку |
| `file.unreadable`, `read.changed` | Источник недоступен или изменился во время чтения |
| `write.hash_mismatch`, `write.busy` | Устарел план или идёт другая запись |
| `index.publish_failed`, `index.stats_failed`, `index.history_failed` | Ошибки на разных стадиях публикации индекса |
| `write.history_failed` | Файл опубликован, запись истории завершилась ошибкой |
| `history.adopt_refs_failed` | Базовое событие добавлено, ссылка head не обновлена |

## Подсказки и исправления

`guidance` использует поставляемый русский каталог ru.json. В обычном ответе режим `compact`. Для ошибок режим `on_error` содержит дедуплицированные подсказки по кодам, ссылки на скилы и документы, где они заданы. Каталог возвращает общую подсказку для неизвестного кода.

`fix --diagnostic ID --preview` использует подходящий предложенный фикс. Одинаковое доказательство, повторённое в одной строке, может сделать фикс неоднозначным. Перед `--apply` проверьте цель, исходный хеш и хеш плана. После применения перечитайте источник и повторите валидацию.
