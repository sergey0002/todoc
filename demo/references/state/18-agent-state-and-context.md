# 18. Агентский стейт и контекст

Состояние датасета лежит в `$XDG_STATE_HOME/todoc/state-<dataset_id>.json`. Если переменная окружения отсутствует, используется `~/.local/state`. Хранятся `schema_version`, `vars` и время обновления. Разрешённый ключ версии 1 — `context.current_project`. Отсутствующий файл читается как пустое состояние.

- `state get KEY` читает значение.
- `state list` возвращает строки с ключом и значением. Доступны проекции, предел и курсор.
- `state set KEY VALUE` и `state unset KEY` готовят план. Запись требует `--apply`. При передаче `--if-plan-hash` проверяется хеш предпросмотра.

`context --change ID` либо `context --tag NAME` объединяет релевантные события, сведения об изменении и файлы. `--with-diff` добавляет диффы для изменения, если доступен базовый образ. `--budget` по умолчанию равен 8000 и считает символы добавляемых фрагментов. Для структурированных фрагментов учитывается длина их JSON-представления. В ответе есть `used_chars` и признак обрезки. Сериализованный конверт вместе с метаданными может превышать это число.

Для проверки состояния фактов на дату используйте `records query --as-of`. Для ленты истории используйте `timeline` с темпоральным и путевым фильтром.
