# 07. Поиск и чтение

## Лексический поиск (`application/search.py`)

Офлайн, детерминированно, без внешнего индекса.

1. **Токенизация**: `[a-zA-Z0-9_\u0400-\u04ff]+`, нижний регистр — латиница, цифры, кириллица.
2. **Отбор кандидатов**: документы со статусом `ok`, фильтр `--type`, фильтр `--within`
   (путь равен префиксу или лежит внутри него).
3. **Совпадение**: термин считается найденным, если встречается в нижнем регистре текста
   документа (подстрока, не граница слова).
4. **Ранжирование**: `score = совпадения_в_заголовке × 10 + число_найденных_терминов`;
   сортировка по убыванию score, при равенстве — по `document_id`.
5. **Фрагмент**: окно вокруг первого совпадения (−80/+160 символов, не длиннее 240),
   с номерами строк `line_start`/`line_end` и флагом `truncated`.
6. **Breadcrumb**: для Markdown — первые три заголовка документа.
7. **Бюджет**: `--budget N` ограничивает суммарный размер фрагментов в байтах UTF-8;
   остановка происходит не раньше первого результата.

Ответ: `{total, returned, truncated, cursor, items[]}`; `items[]` содержит `id`, `path`, `title`,
`heading_path`, `rank`, `relevance{method: "lexical", matched_by}`, `matched_terms`, `snippet`.

Проверено на демо: `docs search --query "портабельность" --limit 3` → `total 42, returned 3,
cursor "3"`, первый результат — карточка конкурента.

### Что важно знать агенту

- `relevance.method` всегда `lexical`: гибридного и векторного ранжирования в MVP нет.
- `cursor` возвращается, но **не продолжает выдачу** — см. [11-known-issues.md](11-known-issues.md).
- Каждый запуск поиска пересобирает индекс.
- Текст документа для поиска собирается как `заголовок + заголовки разделов + полный текст`.

## Чтение с проекцией (`docs read`)

Общие поля ответа: `dataset_id`, `id`, `path`, `format`, `doc_type`, `hash`.

### Markdown

| Селектор | Что возвращает |
|---|---|
| без селектора | `title`, `headings[]` (`title`, `level`, `line`, `anchor`), `text` (до `--budget`, по умолчанию 4000 символов) |
| `--section` / `--anchor` | `section`, `heading_path`, `lines[]`, `text` — окно до 40 строк от заголовка |
| `--line-range N-M` | `lines[]`, `text` |

Совпадение раздела — по точному заголовку или якорю. Проверено: чтение раздела
«Что агент может считать стабильным» вернуло 16 строк.

### JSON

| Селектор | Что возвращает |
|---|---|
| без селектора | `value` — весь документ |
| `--pointer /a/b/0` | `value` — поддерево по RFC 6901 |

### CSV

| Селектор | Что возвращает |
|---|---|
| без селектора | `columns`, `rows[]`, `total` |
| `--columns a,b` | только указанные колонки |
| `--rows N` | не более N строк |
| `--where key=value` | строки с точным совпадением |

**Порядок применения**: сначала `--rows`, затем `--where`. Поэтому `--rows 3 --where doc_type=guide`
может вернуть ноль строк, хотя `--rows 75 --where doc_type=guide` возвращает три (проверено).

### Opaque

Файлы неизвестного формата возвращают `text` с обрезкой по бюджету.

## Дисциплина бюджета

- Начинайте с `docs search --limit 3`, а не с чтения всего.
- Полный текст запрашивайте только по выбранному `id`.
- Для больших документов используйте `--section` или `--line-range`.
- `--budget` ограничивает байты ответа, но не отменяет пересборку индекса.
