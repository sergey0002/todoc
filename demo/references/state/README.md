# Состояние системы `todoc` — документация

Каталог `docs/state/` описывает **фактическое текущее состояние** реализации: что работает,
как устроено, как проверяется и что известно как дефект. Каждый факт здесь получен прогоном
кода или CLI; непроверенные утверждения помечены явно. Цель каталога — 100% покрытие
реализованного кода: каждой подсистеме и каждой команде есть раздел, у каждой возможности —
ссылка на источник (план → задача → идея/баг).

Документация сверена с объединённым деревом `2c0085a` и текущим демо.
Справочник содержит 69 листовых (включая скрытый alias `docs mv`) команд. Приёмка и измерения приведены отдельно.

## Как обновлять этот каталог

1. Любой факт (число, код, поведение) добавляется только после проверки командой.
2. Числа в [10-testing-and-quality.md](10-testing-and-quality.md) обновляются при каждом изменении кода.
3. Новый дефект попадает в [11-known-issues.md](11-known-issues.md) и в `demo/bugs/` с командой воспроизведения.
4. Если меняются команды, обновите cli.md через `PYTHONPATH=src python tools/render_cli_reference.py`.
   Сверьте смысл контракта с [03-cli-reference.md](03-cli-reference.md).
5. Новая подсистема получает свой раздел (17–19 — образец) со ссылками на план-источник.
