# 12. Работа агента с датасетом

В начале сессии откройте карту датасета или выполните точечную выборку. Проверьте один вызов до запуска зависимого пакета. Для скилов используйте `skills tree` и затем `skills read --path <путь>`. Канонические процедуры находятся в [контракте агента](../../notes/agent-contract.md).

1. **Обзор.** Для списков идей, планов и багов используйте `docs list --type T --fields id,path,title,status`. Проверьте `complete` и продолжайте с `next_cursor`. Для неизвестного содержания используйте `docs search`.
2. **Чтение.** Открывайте нужный `id` и фрагмент. Сохраняйте путь, координаты и хеш. `--budget` текстовых форм считает символы Unicode.
3. **Типы.** `types show` показывает описатель и ассеты. `types prompt TYPE --op create` выдаёт стартовый промпт типа. Для полей фильтра используйте `docs list --filter-fields`.
4. **Запись.** Используйте preview и проверяйте область, цель и хеш. Передайте поддерживаемое предусловие в `--apply`. Сразу перечитайте источник и выполните `validate --all`. Для поддерживаемой прямой правки сначала просмотрите `sync PATH`, затем примените `sync PATH --apply`.
5. **При ошибке.** Остановите зависимые действия. Смотрите `diagnostics`, `guidance` и предложенное действие. При `write.history_failed` сначала подтвердите уже сохранённый файл и его хеш.

Многофайловую правку удобно вести через `change open`, `change show`, просмотр и проверку дельт, затем `change apply`. События доступны через `log`, `blame`, `timeline` и `context`. Для пакетных процедур проверяйте, что после первого ошибочного вызова дальнейшие действия остановлены.
