# Идея: самодокументируемое поле `guidance` для моделей во всех выводах CLI и переключаемый `i18n`-каталог подсказок

- Тип: `idea`
- Создан: 2026-11-27
- Идентификатор: `doc:ideas/cli-model-guidance-and-hint-catalog.md`
- Статус: `planned` (базовое ядро включено в `doc:plan/bmad-wave-planning-skills.md`)

## Суть

Закрепить как стандарт всего `todoc` CLI (и принцип `P15` Конституции) специальное информационное поле **`guidance`** для моделей во **всех форматах вывода** (`json`, `markdown`, `table`) как при успехе (`ok: true`), так и при ошибках (`ok: false`), а сами тексты рекомендаций, ссылки на скилы (`skills`), ссылки на документы (`docs`) и шаблоны команд дальнейших действий хранить отдельно от Python-кода в компактном переключаемом каталоге ключ-значение по принципу **`i18n`** (`code → подсказка + ссылки по профилю`).

## Проблема

Проверка текущего кода `src/todoc/output/envelope.py` и `src/todoc/cli.py` выявила четыре системных пробела:
1. **Нет единого поля подсказок для модели со ссылками на скилы и документы:** в `Envelope` сейчас есть только `diagnostics` (сухие факты ошибки) и `next_actions` (`argv + purpose`). В конверте нет стандартного блока, куда валидатор или тест мог бы положить рекомендацию для модели со ссылками на более подробный скил (`process/bmad/... --mode guided`) и справочные документы (`notes/agent-contract.md`), а часть режимов (`--output markdown` в отдельных командах) вообще опускает конверт.
2. **Подсказки зашиты строками прямо в Python-код:** фразы вроде `"Показать план исправления первой диагностики"` размазаны по десяткам мест в `src/todoc/cli.py`. Нельзя поменять формулировки, язык или подробность подсказок без правки кода и риска сломать строковые ассерты в тестах.
3. **Дилемма «сильная vs слабая модель»:** если давать длинные разжёванные инструкции всегда на входе, сильная модель теряет свободу и сжигает контекст; если не давать их вообще, слабая модель застревает на первой же ошибке валидации.
4. **Нет автотестов на качество самодокументации ошибок для модели:** сейчас тесты проверяют код возврата, но не гарантируют, что любая ошибка CLI даёт модели понятный выход из тупика.

## Предложение

### 1. Политика прогрессивной опоры (Конституция `P15`)

- **На входе флоу** модель получает компактный, не сковывающий свободу скил (`compact` — цель, инварианты результата и жёсткие границы).
- **Если у модели всё получается с первого раза (`ok: true`)**, информационное поле `guidance` остаётся минимальным (`{"mode": "compact", "hint": null, "skills": [], "docs": []}` или 1 короткая навигационная строка без воды) — сильная модель не получает лишнего шума и спокойно игнорирует пустой блок.
- **Если модель валится на проверке / тесте / валидации CLI (`ok: false` или диагностика ошибки/предупреждения)**, CLI по коду ситуации автоматически подтягивает из каталога развёрнутую рекомендацию в поле `guidance`: объяснение причины, ссылки на подробный скил с готовым эталоном (`skills`, в т.ч. `--mode guided`) и ссылки на документы (`docs`), а также готовые `next_actions`.

### 2. Стандартное поле `guidance` в любом ответе CLI (ошибочном и неошибочном, во всех форматах)

- В `Envelope` (`src/todoc/output/envelope.py`) добавляется стандартное поле верхнего уровня **`guidance`**:
  ```json
  {
    "schema_version": 1,
    "ok": false,
    "data": {},
    "diagnostics": [{"code": "wave.card_incomplete", "severity": "error", "path": "plan/roadmap-core.md", "message": "..."}],
    "next_actions": [
      {"argv": ["todoc", "--root", "demo", "skills", "read", "--path", "process/bmad/bmad-slice-roadmap", "--mode", "guided"], "purpose": "Открыть скил нарезки волн с готовым эталоном карточки волны"}
    ],
    "guidance": {
      "profile": "ru",
      "mode": "on_error",
      "items": [
        {
          "code": "wave.card_incomplete",
          "hint": "У каждой волны обязателен говорящий заголовок результата и 4 тезиса простыми словами без .py/doc:id.",
          "skills": ["process/bmad/bmad-slice-roadmap --mode guided"],
          "docs": ["plan/bmad-wave-planning-skills.md#4.3"]
        }
      ]
    }
  }
  ```
- В режимах `--output table` и `--output markdown` `emit()` всегда рендерит компактный, однозначно парсируемый блок `guidance:` (`hint`, `skills`, `docs`), и при `ok: true`, и при `ok: false`.

### 3. База подсказок по принципу `i18n` (коды в коде — тексты и ссылки в декларативном файле)

- **В Python-коде и валидаторах зашиты только стабильные машинные ключи ситуаций** (`code`, например `wave.card_incomplete`, `wave.jargon_in_summary`, `markdown.tags_invalid`, `staleness.drifted`, `skills.not_found`, `usage.error`, `ok.plan.portfolio`) и безопасный словарь параметров подстановки (`{root}`, `{path}`, `{id}`, `{doc_type}`).
- **Формат хранения базы подсказок:**
  - Базовый runtime-формат — компактный плоский **`JSON` по принципу `i18n`-словарей** в `src/todoc/resources/guidance/<profile>.json` (`ru.json`, `en.json`, `terse.json`): читается стандартным `json` за `< 1 мс` без новых runtime-зависимостей (в отличие от `YAML`, требующего `PyYAML` в рантайме), нативно хранит списки `skills`, `docs` и `actions`.
  - Дополнительно поддерживается плоский табличный экспорт/импорт в **`CSV`** (`code,compact_hint,guided_hint,skills,docs` со склейкой списков через `|`), чтобы человек мог удобно просматривать и править всю матрицу подсказок в табличном редакторе.
  - Для кастомных типов конкретного датасета допускается декларативный оверрайд `.todoc/guidance.json` со строгим соблюдением конституционного принципа безопасности **`P10`**: из `DATA_ROOT` разрешены только текст `hint`, относительные пути `skills`/`docs` внутри датасета и аргументы команд `todoc` (никаких произвольных shell-команд).
- **Переключение вариантов (`i18n` / профилей подсказок):**
  - Через сессионный стейт `todoc state set agent.guidance_profile ru|en|<profile>` и `agent.guidance_mode auto|compact|guided` можно на лету менять язык и стиль/подробность подсказок (например, для A/B-замеров расхода токенов и проходимости разных моделей) без единой правки Python-кода.

### 4. Стандарт автотестов самодокументации CLI для моделей

1. **Инвариант присутствия (`test_guidance_field_present_everywhere`):** любой вызов CLI (`ok: true` и `ok: false`, включая ошибки аргументов, валидации и конфликта хэшей) во всех форматах (`json`, `table`, `markdown`) обязан возвращать валидный блок `guidance`.
2. **Инвариант полноты каталога (`test_all_diagnostic_codes_covered_by_catalog`):** каждый код ошибки `TodocError` / `ValidationError` / `Diagnostic` в `src/todoc/` обязан покрываться записью (или префиксным правилом семейства `markdown.*`, `skills.*`) в системном каталоге подсказок.
3. **Инвариант целостности ссылок (`test_guidance_links_resolve`):** все пути `skills` и `docs`, указанные в каталоге подсказок для демо-датасета, обязаны реально существовать и не нарушать `is_within_root` (`P10`).
4. **Независимость тестов логики от формулировок (`test_profile_switch_preserves_codes`):** переключение профиля подсказок (`ru` ↔ `en`, `compact` ↔ `guided`) меняет текст в `guidance`, но не меняет `code` в `diagnostics`, поэтому бизнес-тесты никогда не бьются при редактуре текстов подсказок.

## Открытые вопросы

- Какой формат сделать основным в пакете, а какой — обменным: компактный `JSON` (`src/todoc/resources/guidance/<profile>.json`) — основной zero-dependency рантайм, `CSV` — табличный экспорт/импорт для массовой вычитки человеком (закрыто).
