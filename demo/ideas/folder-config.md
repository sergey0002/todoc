# Идея: `.config.json` — самоописание папок

**Статус:** идея, не перешла в план. Продолжение линии «скилы как dir_type»
([skills-engine](skills-engine.md)) и общей модели типов todoc.

## Суть

Спец-файл **`.config.json`** в папке датасета: машиночитаемое самоописание —
заголовок, описание, порядок сортировки, иконка/цвет. CLI читает конфиги при
обходе и отдаёт человеку и агенту **описания папок прямо в выводе** — `docs tree`,
`skills tree`, `explain-path` перестают быть списком путей и становятся
сопроводительной картой: заголовок по-русски, описание, что здесь лежит и зачем.
Тот же конфиг — источник описаний для дерева скилов: сканер пробегает папки типа
`skill`, из `.config.json` берёт описание раздела, из SKILL.md — описание скила.

## Проблема

1. **Папки молчат.** `dir_type` отвечает на вопрос «какой это тип», но не «что здесь».
   `docs tree` печатает пути без смысла; агент и человек угадывают назначение папки
   по имени (`notes/`? `inbox/`? что из них куда класть созвон?).
2. **Иерархия скилов без подписей.** В [skills-engine](skills-engine.md) разделы
   хранилища — обычные папки: `coding/`, `coding/git/` — но у них нет описаний,
   и дерево решений получается меню без пояснений к пунктам.
3. **Порядок отображения случаен.** Дерево сортируется алфавитом; важный раздел
   `process/` тонет между `misc/` и `tmp/`. Задать порядок нечем.
4. **Альтернативы хуже.** README в каждой папке шумит в `docs tree` и индексе
   (лишние документы), комментарии в коде не видны CLI, конфиг в `.todoc/` оторван
   от места (нельзя посмотреть, открыв папку, и не переносится вместе с ней при
   копировании подраздела).

## Принципы

1. **Данные, не код.** `.config.json` — декларативный JSON со `schema_version`,
   валидируется как остальная конфигурация todoc; ничего не исполняется (P3, P10).
2. **Служебный файл, не документ.** Файл исключается из индекса документов
   (как содержимое `.todoc/`): не попадает в `docs search`, не ломает счётчики,
   читается только сканером и CLI-выводом.
3. **Отсутствие — не ошибка.** Папка без `.config.json` валидна; файл — опциональное
   обогащение, а не обязательная плата (в отличие от `type.json` типов, где пустой
   описатель — ошибка конфигурации).
4. **Точка истины — файл рядом с данными.** Конфиг живёт в самой папке, переносится
   с ней (скопировал раздел скилов — перенёс и описания).
5. **Бонусом для скилов: каноническое место метаданных раздела.** description
   раздела скилов не надо выдумывать из SKILL.md первого попавшегося скила.

## Предложение

```json
{
  "schema_version": 1,
  "title": "Гит-скилы",
  "description": "Скилы работы с git: коммиты, релизы, ветки. Подраздел coding.",
  "order": 10,
  "icon": "git-branch",
  "lang": "ru",
  "tags": ["git", "vcs"]
}
```

| Поле | Тип | Обязательное | Смысл |
|---|---|---|---|
| `schema_version` | int | да | всегда 1 |
| `title` | string ≤ 80 | да | короткий заголовок для CLI-вывода |
| `description` | string ≤ 500 | нет | назначение папки; для разделов скилов — что внутри |
| `order` | int | нет | порядок в дереве (меньше — выше); без него — алфавит |
| `icon` | string | нет | имя иконки (UI-метаданные, P не исполняется) |
| `lang` | string | нет | язык заголовка/описания |
| `tags` | list[string] | нет | ключевые слова; участвуют в `--query`-фильтрах |

Неизвестные поля — диагностика `folder.config.unknown_field` (та же философия, что
`config.unknown_field` у описателей типов: конфиг, молча принимающий лишнее, хуже
отказавшегося).

## Изменения CLI

| Команда | Что меняется |
|---|---|
| `docs tree` | рядом с путём — `title` (если есть) и обрезанное `description`; `--format json` добавляет `folder_meta` |
| `skills tree` (из [skills-engine](skills-engine.md)) | заголовки и описания **разделов** — из `.config.json`; описания скилов — из SKILL.md, как раньше |
| `explain-path` | доп. блок `folder_meta`: заголовок и описание папки назначения |
| `docs search` | `tags` из конфигов разделов участвуют в матчинге запроса (вес низкий) |
| `index rebuild` | конфиги читаются сканером, попадают в поколение индекса |

## Валидация (коды `folder.*`)

| Код | Когда |
|---|---|
| `folder.config.invalid_json` | синтаксическая ошибка JSON с локацией |
| `folder.config.unknown_field` | неизвестное поле |
| `folder.config.bad_type` | поле не того типа / длиннее лимита |
| `folder.config.bad_order` | `order` не int |

Файлы `.config.json` в датасете «скилы»: правило поиска — сканер смотрит только на
верхний уровень каждой dir_type-папки (не рекурсивно в чужие типы).

## Роутинг агента (дополнение к skills-engine)

```markdown
3. Дерево малопонятно или пусто по описаниям — прочитай конфиг раздела:
   todoc docs read --root skills --path skills/coding/git/.config.json
```

(файл читается как обычный JSON через существующий CLI — отдельная команда не нужна).

## Сценарии (WHEN/THEN)

```markdown
#### Scenario: Дерево с описаниями
- **WHEN** в skills/coding/git/ лежит .config.json с title «Гит-скилы»
- **THEN** skills tree печатает «coding/git — Гит-скилы: Скилы работы с git…»
  без чтения человеком конфига вручную

#### Scenario: Папка без конфига
- **WHEN** .config.json отсутствует
- **THEN** папка выводится как раньше (путь), 0 диагностик

#### Scenario: Битый конфиг
- **WHEN** .config.json содержит неизвестное поле "color"
- **THEN** validate выдаёт folder.config.unknown_field с путём и JSON-локацией;
  дерево работает, поле игнорируется (fail-open на вывод, fail-closed на валидацию)
```

## План внедрения

- **Фаза 1 — парсер и валидация.** Чтение `.config.json` сканером, коды `folder.*`.
  Приёмка: битые конфиги дают точные диагностики, отсутствующие — 0 диагностик.
- **Фаза 2 — вывод.** `docs tree` и `explain-path` с `folder_meta`; JSON-конверт.
  Приёмка: демо-датасет с 3+ конфигами показывает заголовки.
- **Фаза 3 — skills tree.** Описания разделов из конфигов; интеграция с деревом скилов.
  Приёмка: демо-хранилище скилов печатает русские заголовки разделов.
- **Фаза 4 — поиск.** `tags` в лексическом матчинге. Приёмка: запрос по тегу находит
  документы раздела выше, чем до тегов.

## Открытые вопросы

- Наследование: раздел без описания наследует родительское? (рекомендация: нет —
  явность, иначе молчаливая семантика).
- Конфликт «description в конфиге vs первый параграф SKILL.md» для скил-папок:
  конфиг — для разделов, скил описывается своим SKILL.md (рекомендация).
- `.config.json` vs `.todoc/folder-configs.json` централизованно: выбрали рядом
  с папкой (переносимость + видимость); централизованный реестр может пригодиться
  для мульти-рутов — отложить.
- Регистронезависимость: только `.config.json` или также `config.json`?
  (рекомендация: только точное имя, конвенция одна).
- Нужно ли `version`-поле для миграций формата (schema_version достаточно)?
