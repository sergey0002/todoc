# BUG-009: docs suggest нормирует score к максимуму — единственный кандидат всегда 1.0

| Поле | Значение |
|---|---|
| Bug ID | BUG-009 |
| Компонент | application (folder_config.score_folder_configs → docs suggest) |
| Обнаружено | 2026-11-25 — Задача 3 плана folder-config: написание теста reason/words упало на неожиданной нормировке |
| Окружение | todoc 0.1.0 (10d59ea), Python 3.11, Linux |

## Сводка

`score_folder_configs` нормирует raw score делением на максимум среди
кандидатов этой выдачи. Если конфиг в датасете один, его score равен 1.0 при
любом ненулевом совпадении, прошедшем порог 0.25: слабый сигнал «одно слово
alias совпало» (raw 0.3) показывается тем же числом 1.0, что и точный alias
(raw 1.0). Потребитель JSON — агент — читает score как меру уверенности и не
может отличить сильное совпадение от слабого, когда кандидат один (частый
случай: первая папка с конфигом в новом датасете). `reason` частично
компенсирует, но числовое поле вводит в заблуждение; порог 0.25 применяется
уже к нормированной величине, то есть единственный кандидат с любым совпадением
его проходит.

## Шаги воспроизведения

1. Датасет с одним конфигом: `{"schema_version": 1, "title": "Проекты",
   "aliases": "дизайн ванны"}`.
2. `todoc docs suggest --query "ванны"` → `score: 1.0`,
   `reason: "words: ванны (aliases)"` — как при точном alias.
3. Добавить второй конфиг с exact alias «ванны» → первый падает до
   `0.23` (0.3/1.3), что ниже порога — тот же сигнал «исчезает» от появления
   более сильного конкурента, хотя сам сигнал не изменился.

## Ожидаемое поведение

Числовая мера уверенности стабильна независимо от состава выдачи: raw score в
отдельном поле (`score_raw`) и/или нормировка к константе шкалы (максимум
возможного за совпадение этого типа), а не к текущему максимуму кандидатов;
порог применяется к raw.

## Фактическое поведение

score — относительная величина выдачи; при одном кандидате всегда 1.0, при
появлении конкурента падает ниже порога без изменения самого сигнала.
Обнаружено тестом: первая версия `test_score_alias_words_reason` ожидала
`score < 1.0` у кандидата со словом alias и падала на `1.0 < 1.0`.

## Доказательства

- `src/todoc/application/folder_config.py`, `score_folder_configs`:
  нормировка `score / max` с round 4 после сбора raw.
- План folder-config §Фаза A: «нормировка score/max→0..1» — случай одного
  кандидата не оговорён; сценарий идеи предполагает различимую уверенность.
- `tests/unit/test_folder_config.py::test_score_alias_words_reason` — фиксирует
  текущую семантику (0.3 слова против 1.0 exact только при двух конфигах).

## Воздействие

Friction: агент перепроверяет кандидата с 1.0 чтением reason (+1–2 вызова);
при слабом сигнале возможна ошибочно уверенная укладка документа в папку —
риск качества данных без порчи существующих файлов.

## Предложение по исправлению

1. Добавить `score_raw` в элемент `candidates`; порог считать по raw.
2. Нормировку заменить на деление на константу шкалы (max возможного raw для
   типа совпадения) либо не нормировать при n ≤ 1.
3. Выбрать окончательную семантику в Фазе B (gate fixture ≥10) и зафиксировать
   в плане; до того — не менять поведение (тесты уже фиксируют текущее).
