# BUG-007: linkcheck из DoD планов не существует как команда CLI

| Поле | Значение |
|---|---|
| Bug ID | BUG-007 |
| Компонент | cli (проверка ссылок — только внутри validate) |
| Обнаружено | 2026-11-25 — исполнение плана folder-config (запрос 21), шаг «финал» Задачи 6 |
| Окружение | todoc 0.1.0 (95a6c7f после мержа #55), Python 3.11, Linux |

## Сводка

DoD сразу двух планов (skills-vault, folder-config §6) содержит шаг «linkcheck 0»,
но команды `linkcheck` (или `docs links`) в CLI нет: `todoc --help` её не
перечисляет, вызов даёт `usage.error`. Проверка ссылок существует только как
link-диагностики внутри `validate` (`validator._check_markdown_links`), и счётчик
просмотренных ссылок наружу не отдаётся. Агент вынужден эмулировать проверку
разовыми скриптами, и методики расходятся: скрипт по wikilink-регэкспу в запросе 20
насчитал 733 ссылки, движковый парсер markdown в запросе 21 — 976 (разные
определения «ссылки»: inline/autolinks/сноски против одних wikilink).

## Шаги воспроизведения

1. `todoc --help | grep -i link` → пусто; `todoc linkcheck` → `usage.error`.
2. Выполнить шаг DoD плана «linkcheck 0» дословно → нечем: `validate` печатает
   только диагностики и не показывает, сколько ссылок проверено.
3. Подсчитать ссылки скриптом двумя способами: регэксп `\[\[([^\]|#]+)` по
   `demo/**/*.md` → 37 «целей» (почти все — примеры из гайдов, не ссылки);
   движковый парсер (`parse_markdown(...).links` по индексным документам) → 976.

## Ожидаемое поведение

Одна команда даёт проверяемый факт: `todoc docs links --root demo` →
`{"total": N, "broken": 0, "by_file": …}` — тот же парсер и те же правила
резолва, что в validate. DoD-строка «linkcheck 0» выполнима дословно, счётчик
стабилен между запросами.

## Фактическое поведение

Агент каждый раз пишет одноразовый скрипт (в запросе 20 — wikilink-регэксп,
в запросе 21 — два захода: ложный регэксп с 37 «битыми», затем парсер движка),
тратит токены и получает несопоставимые между прогонами числа.

## Доказательства

- `demo/plan/folder-config-implementation.md` §6: «linkcheck 0» (дважды, шаг 4 З6 и DoD).
- §8 того же плана: «linkcheck 733/0» — число из самодельного скрипта запроса 20.
- `todoc --help`: команды нет; `src/todoc/application/validator.py:156`
  `_check_markdown_links` — проверка есть, счётчик не отдаётся.
- Замер запроса 21: 368 документов, 976 ссылок движковым парсером, битых 0.

## Воздействие

Цена за план с таким DoD: ~1500 токенов (поиск команды, два ложных захода
регэкспа, сверка методик); числа между запросами несопоставимы (733 против 976),
что маскирует реальные регрессии ссылок под шумом разных определений.

## Предложение по исправлению

1. Добавить `docs links [--root R] [--file P]`: total/broken поверх существующего
   парсера и резолва validate (один код — ноль расхождений).
2. Пока команды нет — убрать слово «linkcheck» из шаблонов DoD, заменив на
   «validate 0 (link-диагностики входят)».
3. Регресс-тест: `docs links --root demo` — total в стабильном диапазоне,
   broken == 0.

## Исправление (2026-11-25)

Исправлено в commit `62c5945` (PR #57) по «Предложению 1»: команда
`todoc docs links --root R [--limit N]` — инвентаризация локальных ссылок
поверх того же резолва, что в validate (`_wikilink_candidates` /
`resolve_link_target`): `total`, `broken`, `items` (path/target/kind/line),
внешние и якорные ссылки в граф не считаются. DoD-строка «linkcheck 0» теперь
выполнима дословно: на демо — 433 локальных ссылки, 0 битых, `truncated: false`.
