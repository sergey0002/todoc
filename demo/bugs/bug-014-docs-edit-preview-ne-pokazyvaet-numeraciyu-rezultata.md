# BUG-014: docs edit --preview не показывает нумерацию результата

| Поле | Значение |
|---|---|
| Bug ID | BUG-014 |
| Компонент | cli (docs edit: preview, диагностики оп) |
| Обнаружено | 2026-11-26 — тик DoD плана «Интероп-экспорты», ре-анкоринг BUG-011 |
| Окружение | todoc 0.1.0 (master a34068b), Python 3.11.2, Linux |

## Сводка

`docs edit --preview` печатает итоговый текст без номеров строк, а нумерация оп
считается ПОСЛЕ предыдущих op того же патча — проверить якоря следующего патча
без перечитывания файла нельзя. Диагностика ошибок оп без контекста:
`edit.line_out_of_range: Line out of range: 85-94` не сообщает ни длину файла,
ни действующий диапазон после предыдущих op.

## Шаги воспроизведения

1. Патч с `insert_after 7` + последующие op: их `line` относятся к состоянию
   ПОСЛЕ вставки; `--preview` показывает текст без номеров → сверять нечем,
   следующий патч пишется по перечитанному файлу (awk/grep вне CLI).
2. Замена 3 чекбоксов DoD по неверным строкам (66–68 вместо 61–63) прошла
   apply без диагностики (затёрла таблицу рисков); поймал только awk-выводом.
3. `--apply` патча с delete 85–94 на файле 84 строк → `Line out of range: 85-94`
   — без длины файла и без указания, что нумерация пост-op.

## Ожидаемое поведение

- Preview: номера строк результата (или per-op diff с пост-op номерами).
- `line_out_of_range`: длина файла/валидный диапазон и напоминание про
  последовательную нумерацию оп.
- Replace-диагностика: если заменяемый текст не совпал с ожиданием — warning
  (сейчас replace строки молча затирает что угодно).

## Фактическое поведение

Preview — чистый текст; ошибки — диапазон без контекста; replace молчалив.
В сессии это дало 2 лишних итерации на патч и один испорченный раздел,
восстановленный следующим патчем.

## Доказательства

```
$ todoc docs edit … --preview        # текст без номеров строк
$ todoc docs edit … --apply          # Error [edit.line_out_of_range]: Line out of range: 85-94
                                    # (файл 84 строки; why — не сказано)
# awk-сверка нумерации после каждого патча — вне CLI
```

## Воздействие

- Каждый многооп-патч: перечитывание файла для сверки (1–2 вызова сверху);
  риск молчаливой порчи соседних разделов replace-ом (реальный инцидент сессии).

## Предложение по исправлению

1. Preview: `--numbered` (по умолчанию включён) — номера строк итога.
2. Диагностика op: длина файла, валидный диапазон, упоминание пост-op нумерации.
3. Опция replace-охраны: `expect: <старый текст>` — несовпадение → `edit.expect_mismatch`.

## Заметки

- Развитие BUG-004 (line-ops); инцидент тика DoD 26.11 задокументирован в §8
  плана «Интероп-экспорты».

- 2026-11-28: `fixed` — коммит `42037d7`. `docs edit --preview` возвращает `numbered` (итоговые номера после всех операций) и `result_lines`; ошибка диапазона называет текущую длину и последовательную нумерацию; `expect` в replace-операции даёт `edit.expect_mismatch` без записи. Проверка: `tools/bug_acceptance.py --only BUG-014` → `fixed`. Тесты: `tests/cli/test_cli_extra.py::test_docs_edit_preview_numbers_the_result`, `tests/unit/test_storage_contracts.py::test_edit_replace_refuses_expect_mismatch_without_writing`.
