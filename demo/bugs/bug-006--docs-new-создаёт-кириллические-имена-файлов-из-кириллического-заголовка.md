# BUG-006: docs new создаёт кириллические имена файлов из кириллического заголовка

| Поле | Значение |
|---|---|
| Bug ID | BUG-006 |
| Компонент | cli (docs new, слаг из заголовка) |
| Обнаружено | 2026-11-25 — создание флоу-документа пилота и при введении конвенции именования |
| Окружение | todoc 0.1.0 (4b6ae47…a01f733), Python 3.11.2, Linux |

## Сводка

`todoc docs new --title "<русский заголовок>"` наследует кириллицу заголовка в
имени файла, тогда как `change open` для того же кириллического заголовка даёт
латинский слаг (транслитерация). Два пути создания документов в одной системе
именуют файлы по разным правилам; конвенция «русский `title`, файл на английском»
вынуждена требовать явного `--path` на каждый вызов.

## Шаги воспроизведения

1. `todoc docs new --root demo --type plan --title "Документирование софта: типовой профиль" --dir plan`
   → файл `plan/документирование-софта--типовой-профиль-….md` (кириллица в имени).
2. `todoc change open --root demo --title "Пилот: профиль документирования софта"`
   → папка `changes/pilot-profil-dokumentirovaniya-sofa/` (транслитерация).
3. Сравнить правила именования: `grep -n "def slugify" src/todoc/application/changes.py`
   против слага `docs new` в `cli.py`.

## Ожидаемое поведение

Одинаковые правила именования во всей системе. Минимально: `docs new`
транслитерирует кириллицу тем же `slugify` (changes.py:59–74), давая латинское
имя файла; заголовок остаётся в `title`. Явный `--path` остаётся переопределением,
а не единственным способом получить латинское имя.

## Фактическое поведение

Слаг `docs new` переносит кириллицу в имя файла. Обход — только явный `--path`
с латинским слагом, который агент обязан помнить сам; в системе об этом до
введения конвенции (2026-11-25) нигде не было сказано.

## Доказательства

- Пилот плана softdoc: Задача 5 Шаг 2 дословно гласит «slug из кириллического
  заголовка дал бы кириллическое имя файла, а критерий 3 … ссылаются на
  латинское» → обход `--path flows/order-placement.md` внесён в план.
- 9 md-файлов демо с кириллицей в имени (4 плана `plan/`, 5 баг-репортов
  `bugs/`) — все созданы `docs new` без `--path`; json-записей с кириллицей — 0
  (record_id enforce схемами).
- Транслитерация уже реализована в движке: `src/todoc/application/changes.py`
  `slugify` (TRANSLIT-таблица, `[a-z0-9-]`, fallback-хеш).

## Воздействие

Цена для агента за эпизод: знание о необходимости `--path` добывается пробой
или чтением кода (+1–2 вызова, ~800 токенов); каждый кириллический путь в
ссылках и записях (`source_path`) хрупче для набора и копипасты, разнобой
имён ломает единообразие датасета. Не порча данных, обходимо — потому minor.

## Предложение по исправлению

1. В `docs new` использовать тот же `slugify` из `changes.py` (единая функция
   слага системы) — латинское имя из кириллического заголовка автоматически.
2. Опционально: диагностика/предупреждение при кириллическом basename в
   `docs new` без `--path` (до перевода на slugify).
3. Регресс-тест: `docs new --title "Оформление заказа"` →
   `flows/oformlenie-zakaza.md` + `title` кириллический в файле.

## Заметки

## Исправление (2026-11-25)

Исправлено в commit `791fc51` (PR #57) по «Предложению 1»: `docs new` строит
слаг через транслитерацию (таблица TRANSLIT из `changes.py` — единая функция
слага системы, как предлагалось): кириллический заголовок даёт латинское имя
`[a-z0-9-]`, `title` остаётся кириллическим, явный `--path` по-прежнему
переопределение. Проверки: `test_docs_new_transliterates_cyrillic_title`
(«Оформление заказа» → `inbox/oformlenie-zakaza.md` с кириллическим title) и
`test_docs_new_punctuation_only_title_falls_back` (fallback `untitled`).
