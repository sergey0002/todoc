# BUG-001: Явный doc_type без fm-правила резолвится в unknown

| Поле | Значение |
|---|---|
| Bug ID | BUG-001 |
| Компонент | engine (typing_system/resolver.py, правила датасета) |
| Обнаружено | 2026-11-25 — сохранение плана `doc:plan-softdoc-profile` в демо |
| Окружение | todoc 0.1.0 (4b6ae47), Python 3.11.2, Linux |

## Сводка

Документ с явным `doc_type: plan` во front matter резолвится в `doc_type:
unknown`, если в `document-rules.json` нет fm-правила для этого типа. Все четыре
активных плана демо (созданы 25.11.2026) сейчас `unknown` — и валидатор молчит.

## Шаги воспроизведения

1. `todoc explain-path --root demo "plan/агентский-стейт--state-json-в-движке--v1---текущий-проект.md"`
2. Повторить для трёх других планов из `plan/` (все от 25.11.2026).
3. `todoc validate --root demo --all` — диагностик нет.

## Ожидаемое поведение

Явное объявление типа во front matter — высший приоритет резолвера: у fm-правил
приоритет 200, а конституция ставит явное объявление выше правил датасета
(docs/state/16-leftovers-report.md, P1-14: «конституция ставит явное объявление
выше правил датасета»). Ожидание: `doc_type: plan`, `rule_source` со ссылкой на
объявление.

## Фактическое поведение

- `doc_type: unknown`, `rule_source: default` для всех четырёх планов.
- Валидатор даёт 0 диагностик: документ «просто без типа», молча.
- Следствия: фильтры `docs search --type plan` ничего не найдут;
  `required_sections` типа plan не проверяются для этих документов.

## Доказательства

Вывод `explain-path` по трём планам (2026-11-25):

```
unknown | default
unknown | default
unknown | default
```

Каждый файл начинается с `doc_type: plan` во front matter. Открытый дефект уже
описан в `references/state/16-leftovers-report.md` как P1-14 («явный doc_type
без правила») — воспроизведён вживую на реальных документах.

## Воздействие

- Агент: типовые запросы по `--type` дают пустой результат по ключевым
  документам; структурные проверки типа не применяются. Частота — каждый
  документ нового типа без правила.
- Система: молчаливость (0 диагностик) скрывает дефект от check/validate —
  веришь, что всё в порядке.
- Обходимо правилами, но правило нужно знать заранее — у нового типа его нет.
Цена для агента за эпизод: три вызова `explain-path` подряд (по одному на план) плюс сверка с 16-leftovers-report — против одного вызова, если бы явный doc_type резолвился сам.

## Предложение по исправлению

Два уровня:

1. Данные демо: fm-правила для реально используемых типов (`plan`, `note`,
   `bug-report` — последний добавлен сразу с типом). Внесено в план
   `doc:plan-softdoc-profile`, задача 1, шаг 2.
2. Системно (варианты из 16-leftovers-report): C — диагностика «явный doc_type
   без правила» (предупреждение, не отказ), затем B — явные правила
   игнорирования. Вариант A отклонён авторами отчёта (ломает существующие базы).

## Заметки

- Родственный репорт: BUG-002 (частный случай — файлы, создаваемые самим движком).
- Плановая проверка после фикса: `explain-path` каждого плана → `doc_type:
  plan`; критерий 3 плана `doc:plan-softdoc-profile`.

## Исправление (2026-11-25)

Исправлено в commit `5038dd6` (PR #57): `resolve_type` получил явный приоритет
объявления во front matter (конституция P1-14) — явный `doc_type` резолвится в
само себя с `rule_source: front-matter`, даже если ни одно правило его не знает;
согласное fm-правило сохраняет свой источник (`rule:<id>`), несогласные
правила перекрываются объявлением. Проверки: `test_resolve_front_matter_miss`
переписан на новую семантику (+ тест согласия правила), CLI-тест
`test_explain_path_explicit_doc_type_without_rule`; на демо все пять планов
показывают `plan | front-matter`, `validate --all` — 0 диагностик (обязательные
секции типа plan у всех присутствуют). Вариант C из «Предложения» (warning на
объявление без правила) не добавлялся: после фикса такое объявление легально.
