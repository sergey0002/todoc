# BUG-008: skills tree показывает счётчик только собственных скилов раздела

| Поле | Значение |
|---|---|
| Bug ID | BUG-008 |
| Компонент | cli (skills tree, рендер `_skills_tree_text`) |
| Обнаружено | 2026-11-25 — Задача 4 плана folder-config: разделы получили конфиги и заголовки, счётчик стал заметен |
| Окружение | todoc 0.1.0 (2c290af), Python 3.11, Linux |

## Сводка

Заголовок раздела в table-режиме `skills tree` печатает `(N)`, где N — только
скилы, лежащие в папке раздела непосредственно. Для раздела, чьи скилы сидят в
подразделах, печатается `(0)` при непустом поддереве: в demo
`coding/ — Скилы кодинга: git, ревью, окружение, установка пакетов. (0)`, ниже —
6 скилов в `env/`, `git/`, `review/`. Конфиг-разделы (Задача 4 folder-config)
вывели такие заголовки на первый экран — агент и человек читают `(0)` как
«раздел пуст». Попутно в том же рендере coverage-замер выявил мёртвую ветку
`if depth >= max_depth: return` (границы глубины уже обеспечивает пре-фильтр
`shown` по `_depth < max_depth`) — удалена в коммите fabf1f0 (PR #55, 25.11.2026).

## Шаги воспроизведения

1. `todoc skills tree --root demo --output table` (после Задачи 6: у разделов
   есть конфиги с заголовками).
2. Строка `coding/ — Скилы кодинга: git, ревью, окружение, установка пакетов. (0)`.
3. Сравнить с поддеревом: `env/ (1)`, `git/ (2)`, `review/ (3)` — суммарно 6.

## Ожидаемое поведение

Счётчик раздела каскадный — `(6)` для `coding/`; либо семантика «own» заявлена
явно в выводе/доках и не вводит в заблуждение на заголовках с конфиг-описаниями.

## Фактическое поведение

`(0)` в строке раздела с шестью живыми скилами ниже; семантика «own» нигде не
документирована.

## Доказательства

- Вывод `todoc skills tree --root demo --output table` (демо-датасет после З6).
- `src/todoc/cli.py`, `_skills_tree_text`: `own = [s for s in here if s["section"] == section]`
  — только точное совпадение секции.
- Тест `test_tree_sections_from_config_order_and_titles` не покрывает счётчик.

## Воздействие

Friction: агент перепроверяет «пустой» раздел дополнительным вызовом
(`skills tree --within coding` или `skills read`), ~400 токенов за эпизод; риск
неверного маршрутизации диспетчером (раздел с (0) выглядит бесперспективным).

## Предложение по исправлению

1. Каскадный подсчёт в рендере: own + descendants (сумма по поддереву).
2. В JSON-вывод добавить counts на узел (`own`, `cascade`) — для тестов и агентов.
3. Регресс-тест: строка `coding/` содержит `(6)`.

## Исправление (2026-11-25)

Исправлено в commit `791fc51` (PR #57) по «Предложению 1»: счётчик раздела в
`skills tree` каскадный — own + все скилы подразделов; узел с непустым
поддеревом печатается даже без собственных скилов и конфига. Вывод без
конфигов сохраняет прежний формат строк (листовые разделы own == cascade).
JSON-поля `counts` на узел (предложение 2) не добавлялись — счётчик в каждой
строке table уже каскадный; вернёмся при необходимости в плане lifecycle.
Проверки: `test_skills_tree_section_counts_include_descendants` (для demo:
`coding/ (6)` при 0 собственных скилах).
