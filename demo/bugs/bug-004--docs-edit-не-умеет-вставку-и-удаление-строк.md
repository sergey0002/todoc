# BUG-004: docs edit не умеет вставку и удаление строк

| Поле | Значение |
|---|---|
| Bug ID | BUG-004 |
| Компонент | engine (application/write.py, CLI docs edit) |
| Обнаружено | 2026-11-25 — наполнение скелета плана, созданного `docs new` |
| Окружение | todoc 0.1.0 (4b6ae47), Python 3.11.2, Linux |

## Сводка

Единственный поддерживаемый op патча `docs edit` — замена строки целиком
(`{line: N, text: "..."}`). Вставить или удалить строку невозможно, поэтому
наполнить содержательный документ (план, репорт) внутри CLI нельзя: приходится
писать файл напрямую, минуя review-first и журнал истории.

## Шаги воспроизведения

1. `todoc docs new --root demo --type plan --title "T" --dir plan` — скелет.
2. Попытка заменить 8 строк шаблонного комментария на 80 строк содержания через
   `docs edit --patch-file`: на каждую строку контента нужен op с существующим
   `line`; новых строк добавить некуда.
3. Прямая запись файла — единственный путь; затем `todoc docs read` подтверждает
   содержимое, но журнал `.todoc/history/` события не получил.

## Ожидаемое поведение

- По `docs/state/02-architecture.md` (`write.py` — «line-операции правки»)
  ожидались операции вставки/удаления, а не только замены.
- Минимум: при невозможности вставки CLI должен предлагать задокументированный
  канонический путь наполнения, не оставляя прямой файл единственным вариантом.

## Фактическое поведение

`apply_edit_ops` (`src/todoc/application/write.py`, строки ~164–184) только
заменяет существующие строки:

```python
lines = target.read_text(encoding="utf-8").splitlines()
for op in ops:
    line_no = int(op.get("line", 0))
    ...
    lines[line_no - 1] = str(op.get("text", ""))
```

Вставка «строки 41 при 40 существующих» даёт `edit.line_out_of_range`.

## Доказательства

Сессия 2026-11-25: план `doc:plan-softdoc-profile` (525 строк) и 5 баг-репортов
этой папки наполнены прямой записью файла после `docs new`; каждый раз в
отклонениях зафиксировано «наполнение в файл, проверка через CLI».
Проверка кода — `write.py:164-184`, патч-формат `[{"line", "text"}]`.

## Воздействие

- Агент выталкивается за границу системы на самом частом сценарии (создание
  содержательного документа): теряется запись в history, hash-лок (`--if-hash`)
  не защищает наполнение, review-first превращается в конвенцию.
- Частота — каждый содержательный документ; обходимость есть, но ценой
  двух гарантий движка.
Цена для агента за эпизод: попытка пройти CLI (скелет + анализ ограничений патча), затем обходной путь прямой записью и обязательное чтение назад через `docs read` — 3+ вызова и несколько тысяч токенов против одной прямой записи файла.

## Предложение по исправлению

1. Расширить ops: `{"op": "insert_after", "line": N, "text": [...]}` и
   `{"op": "delete", "line": N}` с обратной совместимостью (op без поля `op` =
   replace, как сегодня); история и `--if-hash` — как у replace.
2. До внедрения — задокументировать текущий обходной путь (наполнение в файл +
   обязательное чтение назад) в AGENTS.md и `docs/state/03-cli-reference.md`.

## Заметки

- Не дублирует BUG-005 (то — про чтение, это — про запись).
- Кандидат в план вместе с планом жизненного цикла (review-first механики).

## Исправление (2026-11-25)

Исправлено в commit `0d247a4` (PR #57) по «Предложению 1»: `apply_edit_ops`
принимает `{"op": "insert_after", "line": N, "text": str|list}` (N=0 — в начало,
N=len — в конец), `{"op": "delete", "line": N[, "to": M]}`; op без поля `op`
остался заменой (обратная совместимость); последовательное применение — номера
строк относятся к состоянию после предыдущих op; история и `--if-hash` — как у
замены; неизвестный op — `edit.op_unknown`. Проверки: 5 unit-тестов
(вставка строкой/списком/в конец, удаление одиночное/диапазоном, replace,
op_unknown, out_of_range) + CLI-тест preview/apply на сборке
- 2026-11-26 — gap проявился: replace-блока нет (N строк → M строк = delete+insert
  с ручным расчётом пост-op нумерации); replace по неверным строкам затёр таблицу
  рисков плана интероп-экспортов (восстановлено; см. BUG-014 — preview без
  нумерации и молчаливый replace).
вставка+удаление+шапка; наполнение документов теперь возможно внутри CLI.
