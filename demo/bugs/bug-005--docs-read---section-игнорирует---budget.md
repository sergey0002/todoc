# BUG-005: docs read --section игнорирует --budget

| Поле | Значение |
|---|---|
| Bug ID | BUG-005 |
| Компонент | cli (docs read, ветка section) |
| Обнаружено | 2026-11-25 — чтение раздела 4 плана `doc:plan-softdoc-profile` |
| Окружение | todoc 0.1.0 (4b6ae47), Python 3.11.2, Linux |

## Сводка

При `docs read --id ... --section "..."` флаг `--budget` принимается и молча
игнорируется: окно секции всегда обрезается константой `SECTION_MAX_LINES = 40`
строк. Агент, запросивший секцию с бюджетом 12000 байт, получает 40 строк и
должен сам заметить флаг `truncated`.

## Шаги воспроизведения

1. `todoc docs read --root demo --id doc:plan-softdoc-profile --section "4. Архитектура и файловая карта" --budget 12000`
2. В ответе: `line_start: 131`, `line_end: 170`, `truncated: true` — 40 строк
   при секции длиной ~174 строки (заголовки `## 5.` на строке 305).

## Ожидаемое поведение

Один из вариантов (любой устранил бы молчаливость):

1. `--budget` ограничивает окно секции в байтах: отдать больше 40 строк, пока
   бюджет не исчерпан.
2. Явный отказ: ошибка/предупреждение «--budget не поддерживается с --section»,
   чтобы агент сразу взял `--line-range`.
3. Хотя бы поле `section_total_lines` в ответе рядом с `truncated`.

## Фактическое поведение

Флаг молча игнорируется. Окно жёстко `section_lines[:SECTION_MAX_LINES]`;
переменная `budget` читается в сигнатуре, но в ветке section не используется
(применяется только к полному чтению без `--section`: `text[: budget or 4000]`).

## Доказательства

```
$ todoc docs read --root demo --id doc:plan-softdoc-profile \
    --section "4. Архитектура и файловая карта" --budget 12000
lines: 131 - 170 | truncated: True      ← 40 строк, бюджет проигнорирован

$ todoc docs read --root demo --id doc:plan-softdoc-profile --line-range 186-200
(тот же контент дочитывается только напрямую)
```

Код: `src/todoc/cli.py` — `SECTION_MAX_LINES = 40` (строка 65); ветка section
(строки ~986–1006) не обращается к `budget`; сам 40-строковый лимит
задокументирован в docs/state/07-search-and-read.md («окно до 40 строк») —
дефект не в лимите, а в молчаливом игноре явного флага.

## Воздействие

- Агент полагает, что прочитал секцию в заданном бюджете; хвост секции >40
  строк теряется без ошибки (только `truncated: true`, который легко пропустить
  при авто-парсинге).
- Недочёт, не порча данных: `--line-range` полностью обходит. Частота —
  каждый длинный раздел; именно поэтому severity minor.

## Предложение по исправлению

Вариант 1 (бюджет на окно секции) или 2 (явный отказ) из «Ожидаемого»;
минимальный шаг — вариант 3 (счётчик полной длины в ответе) + строка в
docs/state/07 про поведение флага. Тест: секция >40 строк с `--budget 12000`
и ожидаемое поведение по выбранному варианту.

## Заметки

- Обходной путь уже рабочий и задокументирован в AGENTS.md: дочитывать
  `--line-range` по `line_start`/`truncated`.
- Не дублирует BUG-004 (запись) — это чтение.
