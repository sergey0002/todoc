# Скил: ревью дифа

## When to Use

- Запрошено ревью PR/дифа или агент сам готовит ревью перед merge.

## Procedure

1. `git diff main...HEAD --stat` → масштаб; затем пофайлово `git diff main...HEAD -- <файл>`.
2. Чеклист по каждому файлу: (а) инъекции/пути из недоверенных данных; (б) ошибки обработаны, нет голых except; (в) тесты покрывают новое поведение, а не только счастливый путь; (г) стилю репо соответствует (house-паттерны CLI/тестов); (д) нет мёртвого кода и закомментированных блоков.
3. Замечания ранжируй: блокер / важно / nit; каждый — с файлом:строкой и предложением.
4. Вердикт: «merge», «после правок», «нужно обсуждение» — с одной строкой обоснования.

## Pitfalls

- Не ревьюй стиль там, где есть house-правило — ссылайся на правило (AGENTS.md, agent-contract).
- Не требуй переделки за пределами дифа — фиксируй отдельной задачей.

## Verification

- Каждое замечание проверяемо: файл:строка существует; предложенное изменение воспроизводимо.
