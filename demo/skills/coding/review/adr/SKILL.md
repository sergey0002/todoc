# Скил: ADR из обсуждения

## When to Use

- Принято архитектурное решение (выбор технологии, структуры данных, протокола) — зафиксируй до кода.

## Procedure

1. Собери из обсуждения: проблему, варианты, критерии выбора — только сказанное, не выдуманное.
2. Файл: `docs/adr/NNN-<kebab-slug>.md` (номер — следующий свободный; имя латиницей — конвенция).
3. Структура: `## Контекст` (проблема и ограничения), `## Варианты` (каждый с плюсами/минусами), `## Решение` (что выбрали и почему), `## Последствия` (что это означает практически: + и −).
4. Front matter: `---
id: doc:adr-NNN
title: "..."
doc_type: adr
lang: ru
---` (тип adr обязателен — иначе резолвится неверно).
5. Статусы альтернатив, которые отвергли, сохраняй — это самая ценная часть ADR.

## Pitfalls

- ADR — не туториал: без «как пользоваться», только «почему так».
- Не правь старый ADR задним числом; новое решение — новый ADR со ссылкой на старый.

## Verification

- Прочитай ADR через `todoc docs read --id doc:adr-NNN --section "Решение"` — суть восстанавливается без исходного чата.
