# Скилы взаимодействия: захват, план, исполнение, переходы (жизненный цикл) — план реализации

> **Исполнителю (агенту):** план самодостаточен — читай его, а не историю сессии.
> Работай по задачам сверху вниз; шаги отмечаются чекбоксами (`- [ ]`) в том же
> коммите, который делает шаг. Начинай всегда с первого неотмеченного.

**Цель:** жизненный цикл «идея → план → задачи → готово» работает через 4 скила
взаимодействия поверх существующего CLI; статусы хранятся в самих документах/записях,
переходы — рецепты скилов + две узкие status-команды.
**Спека:** `demo/ideas/skills-engine.md` (механика скилов); решения сессии 25.11.2026:
статус — поле документа (front matter / JSON), без боковых файлов-разметки; переходы —
скилами, не зоопарком CLI; `done/rejected/superseded` — только после явной фразы
пользователя. Ключевые решения продублированы в секциях ниже.
**Стек:** Python 3.11, click, pytest/CliRunner; без новых зависимостей.

## 1. Критерии успеха

1. `todoc docs status --id doc:agent-state-idea` → `{"status": "captured"}`;
   `--set planned` меняет front matter атомарно; `--set foo` → ошибка
   `docs.status_not_allowed`, exit ≠ 0.
2. `todoc records status --id task:shop-0001 --set in_progress` → меняет только
   поле `status`, остальная запись байт-в-байт; `--set blah` → `records.status_not_allowed`.
3. 4 скил-папки в `demo/skill/` (`todoc-capture`, `todoc-plan`, `todoc-execute`,
   `todoc-transitions`) с SKILL.md по стандарту; `docs search` находит каждую по description.
4. Сквозной сценарий: «сохрани идею» → idea `captured`; «делаем» → план `active` +
   идея `planned` + ребро `derived_from`; «поставь задачи» → task-записи с ребром
   `implements`; «готово» → `done` только после подтверждения.
5. pytest зелёный (1215 + новые), 100% покрытие нового кода, `validate --root demo --all` — 0 диагностик.

## 3. Глобальные ограничения

- Скил = папка с SKILL.md (стандарт Agent Skills): `name` lowercase-дефисы ≤64,
  совпадает с именем папки; `description` — «что + когда» ≤1024, с ключевыми словами
  для матчинга. Внутри — конкретные CLI-команды todoc, не «какой-нибудь поиск».
  Хранилище скилов — `demo/skills/` (секции coding/docs/process); диагностики vault
  мержатся в `validate --all`; скилы этого плана — секция `process`.
- Статус хранится **в самом документе**: md → `status:` во front matter, JSON-запись →
  поле `status`. Никаких служебных файлов-разметки рядом.
- Наборы статусов закрытые, объявлены в типе (`allowed_statuses` / schema enum);
  тип без набора = статус свободный; документ без статуса валиден.
- `done`, `rejected`, `superseded` агент ставит только после явной фразы пользователя.
- Все записи атомарны и попадают в history; там, где review-first уже заведён
  (`docs edit`), не ломать; status-команды — прямой сет одного поля с валидацией набора.
- Счётчики демо синхронизируются в README.md, demo/README.md, docs/state/01/13/15 и
  зеркалах demo/references/state/01/13/15; pytest зелёный,
  100% покрытие нового кода — проектное правило.

## 4. Архитектура и файловая карта
