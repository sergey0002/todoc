# Интероп-экспорты: DMN, ASL, Rasa (план реализации)

> **Исполнителю (агенту):** план самодостаточен — читай его, а не историю сессии.
> Работай по задачам сверху вниз; шаги отмечаются чекбоксами (`- [ ]`) в том же
> коммите, который делает шаг. Начинай всегда с первого неотмеченного.

**Цель:** витрины демо-датасета экспортируются в исполняемые внешние форматы (DMN 1.3, ASL, Rasa NLU) из записей, без копипаста и дрейфа.
**Спека:** doc:ideas/interop-exports.md (fm derived_from — якорь файла идеи).
**Стек:** Python 3.11, click, pytest/CliRunner; без новых зависимостей.

## 1. Критерии успеха

1. `flow:order-placement` (tree из записи) экспортируется в ASL-документ, валидный по структуре (States, ветви по `when`/`priority`).
2. Таблица решений правила (`rule:*` examples + дерево флоу) экспортируется в DMN 1.3 XML: decision table с колонкой «Режим» → двоичное решение.
3. 10 терминов глоссария экспортируются в Rasa NLU YML (интенты по терминам, examples из определений).
4. Экспорт — derived-артефакт с fm `derived_from` на записи-источники; правка записи → `todoc stale` видит дрейф; validate = 0 до и после.

## 2. Вне скоупа

- Импорт (обратные конвертеры: внешний формат → записи).
- Исполнение экспортированных документов (runtime), UI-редакторы.
- Экспорты для чужих датасетов (только демо).

## 3. Глобальные ограничения

- Без новых зависимостей: генерация строками-шаблонами; валидность форматов — структурная проверка своими тестами.
- Записи — единственная истина; экспорт не создаёт/не правит записи.
- Review-first: экспорт с --write поверх CAS; записи датасета не трогаются.

## 4. Архитектура и файловая карта

- Create: `src/todoc/application/interop.py` — чистые конвертеры (запись → текст формата), без I/O.
- Modify: `src/todoc/cli.py` — группа `interop export --kind dmn|asl|rasa --id <record_id> [--write PATH]`.
- Create: `tests/unit/test_interop.py`, `tests/cli/test_cli_interop.py`.
- Экспорты пишутся в `exports/` демо (новая папка, dir_type при необходимости).
